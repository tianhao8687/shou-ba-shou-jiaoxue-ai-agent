# RB-429 外部依赖限流与重试放大

## 适用信号

- `recommendation-api` 或其他调用方持续收到下游 HTTP 429。
- 日志存在 `retry-after`，本地 CPU、内存和实例健康正常。
- 重试流量大于原始请求流量，错误和延迟随重试放大。

## 诊断

当 429、`retry-after` 与 `retry_amplification` 同时出现，而本地实例健康时，根因是外部依赖限流叠加本地重试放大，不是连接池、凭据过期或实例容量不足。不得用重启、扩容消费者、轮换凭据或刷新缓存来掩盖该故障。

## 处置边界

当前 Harbor 工具注册表没有“修改重试预算”“启用请求整形”或“联系外部依赖”的写工具，因此 Agent 必须停止自动动作并转人工。人工处置应遵守 `Retry-After`、降低并发、应用指数退避与 jitter，并与依赖方确认配额；新增工具前必须完成独立审批与验证设计。

## 验证

人工变更后重新读取 429 比例、P95 和重试放大倍数。不能用“已联系供应商”或工具返回成功代替指标恢复。
