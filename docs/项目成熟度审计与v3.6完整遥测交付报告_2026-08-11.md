# Harbor AgentOps v3.6 交付、招聘映射与成熟度复评

> 日期：2026-08-11<br>
> 求职目标：厦门月薪 20K+ AI Agent / AgentOps / AIOps / 企业 AI 应用岗位<br>
> 项目方向：生产事故响应，不是跨境电商<br>
> 技术约束：不使用 Elasticsearch，不使用 Electron

## 1. 最终判断

v3.6 已达到“20–30K Agent 应用与 AgentOps 岗位可作为主项目深入讲解”的水准。它不再只是安全工作流和自编测试：项目实际读取 5,442 万行第三方日志、指标和调用链，用两轮失败完成误差审计，再在全新日期上取得原始盲测 79.17% fault Top-3 / 29.17% 完整 Top-1。交付复查又主动发现无序同分候选会漂移，修复后两次完整重放语义一致，当前运行线为 66.67% / 25.00%；两组结果都通过 10/10 预设门槛。

它仍不等于企业生产级产品。公开混沌数据不是目标公司的影子流量；默认身份是演示 RBAC；普通 production 连接器仍只读；真实本地 Qwen 的 CPU 延迟和大样本稳定性也未达到在线 SLO。准确称呼是：

> 有真实外部遥测盲测、生产控制面和分层故障实验的高完成度工程原型。

## 4. 技术深度与创新点

### 4.1 不是“套框架”

核心难点被实现为明确合同：模型只提建议，服务端重新物化计划；审批、权限和成功标准都不由 LLM 决定。框架更换不会改变安全不变量。

### 4.2 评测本身也是软件系统

v3.6 的 predictor 公共接口没有 oracle 参数。预测原子落盘、SHA-256 固定、重新读取后才允许 scorer 打开答案。它比“在同一个 Notebook 里先读标签再算分”更接近真实模型发布门禁。

### 4.3 Schema 漂移不是口号

真实 Parquet 同时出现 SQL NULL、字符串 `'null'`、node/pod/instance 多列和 TiDB 专属组件域。项目用运行时非空回退、类型化实体和领域指标映射修复，测试专门复现“空 pod 遮住 node”的 bug。

### 4.4 失败不会被删掉

首轮和次轮新日期盲测分别只有故障 Top-3 16.67% 和 20.83%。项目没有降低门槛，而是把两天转为已消耗验证集，修复 taxonomy、实体解析和 TiDB 规则，再使用从未解封的 6 月 19 日验收。这个过程比一张 100 分截图更能体现生产判断。

最终验收后又出现第四类失败：同一批缓存重放时，DuckDB 并行聚合的无序返回会改变同分候选顺序。项目没有挑选能维持 79.17% 的顺序，而是使用与标签无关的单线程聚合和字典序二级键；两次重放取得相同语义指纹和更保守的 66.67% / 25.00%。原始盲测文件仍按原 SHA 保存，修复后结果明确标成“答案已打开后的复现审计”。

### 4.5 不用 Elasticsearch 的理由

离线数据已经是 Parquet，DuckDB 能直接做列裁剪、时间过滤和聚合，部署成本远低于搜索集群。当前需求是可重复离线验证，不是多租户在线日志搜索。未来若变成长期在线检索，再按吞吐、保留期和查询模式评估 ClickHouse、对象存储表格式或搜索系统，而不是为了简历堆组件。

### 5.1 本轮测试实际抓到并修复了什么

本轮不是“先写功能、最后让测试全绿”。发布门真实失败过四次：

1. Windows coverage JSON 使用 `app\store.py`，门禁脚本只认识 Linux 的 `app/store.py`。脚本现会统一路径分隔符，并在关键模块缺失时失败关闭；专门测试覆盖 Windows 路径与缺失模块。
2. 新遥测页面第一次 Axe 扫描发现小字号辅助文字的对比度为 2.82–4.23，低于 WCAG AA 的 4.5。没有关闭规则，而是加深颜色；修复后桌面 Chromium 与 Pixel 7 全部通过。
3. PostgreSQL 测试第一次新库通过，第二次运行失败：`DROP EXTENSION vector CASCADE` 会删除向量列和索引，却留下知识表外壳。初始化现会在 advisory lock 内补回 `embedding`、回填全部 chunk、恢复 `NOT NULL` 与 HNSW。测试先制造这个残缺状态，再让两个并发副本恢复，并连续运行两次。
4. 完整遥测第一次断网复跑仍过 10/10 门槛，却有 23 个案例的候选顺序漂移；故障 Top-3 从 79.17% 变为 75.00%。根因是无序 SQL 聚合与 Python 同分稳定排序叠加。现在聚合与二级键都有确定合同，CI 比较排除生成时间和耗时后的语义指纹；两次复跑均为 66.67% / 25.00% 且语义哈希一致。

这些失败比“测试最后全绿”更重要，因为它们分别证明了跨平台门禁、用户可访问性、数据库灾后恢复和评测可复现性确实参与交付判断。

## 7. 最适合与不适合投递的岗位

优先：AI Agent 应用工程师、Agent 平台工程师、AgentOps/AIOps、企业 AI 应用后端、LLM 工程化、RAG/工作流工程师。

需要补另一个主项目：纯 SFT/RLHF/GRPO 算法岗、CUDA/推理内核、纯多模态训练、机器人控制。Harbor 能证明应用与平台工程，不能替代模型训练研究经历。

## 8. 面试主线

推荐按五句话回答：

1. 业务：这是生产事故响应控制面，不是聊天机器人。
2. 约束：LLM 不持有生产权限，计划、审批、能力令牌和验收由确定性代码控制。
3. 可靠性：任务持久化，多个 Worker 用 lease/fencing/幂等处理崩溃和重复执行。
4. 证据：除了 105 项密封回归，还跑了 5,442 万行第三方遥测；原始盲测是 79.17% / 29.17%，修复确定排序后的可复现运行线是 66.67% / 25.00%，不隐瞒回落。
5. 边界：它是高完成度工程原型，不是企业上线认证；下一步是授权影子流量、长期漂移和真实模型 A/B。
